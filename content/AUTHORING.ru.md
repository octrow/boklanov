# Как редактировать сайт boklanov.com

> Источник правды - папка `content/productions/`. На каждый спектакль —
> папка с четырьмя файлами:
> `index.yaml` (поля), `bodyRu.mdx` / `bodyEn.mdx` / `bodyDe.mdx` (тексты).
>
> **Два способа редактировать:**
> 1. **Через браузер**, на `boklanov.com/keystatic` — визуальный редактор
>    с формами и кнопкой «Save». Самый простой путь, ничего ставить не нужно.
> 2. **В Obsidian** (как раньше) — для тех, кому удобнее работать с
>    `.yaml` и `.mdx` напрямую.
>
> В обоих случаях сайт пересобирается автоматически через 1–2 минуты
> после сохранения / commit-and-sync.

---

## Способ 1: браузер (Keystatic)

Самый простой путь — никакой установки.

1. Открыть `https://boklanov.com/keystatic` (на телефоне тоже работает,
   но удобнее с ноутбука).
2. Войти (по ссылке из email — Daniil отправит приглашение).
3. Выбрать **Productions** в боковой панели → нужный спектакль.
4. Править поля в форме. Длинные тексты (RU/EN/DE) — три отдельных
   таб, как Word. Картинки — drag-and-drop.
5. Нажать **Save** наверху. Через 1–2 минуты сайт пересобирается.

Картинки автоматически загружаются на CDN (R2). Никому ничего писать не
нужно.

---

## Способ 2: Obsidian (для опытных)

Если хочется работать с файлами напрямую — например, делать массовые
правки или работать оффлайн.

### Один раз: установка

### 1. Установить Obsidian

Скачать с [obsidian.md](https://obsidian.md) - бесплатно, macOS / Windows / iOS / Android.

### 2. Получить от Daniil: Personal Access Token

GitHub PAT нужен для записи. Daniil создаёт токен на своей стороне и
отправляет тебе в Telegram. Хранить токен в безопасном месте (Keychain,
1Password, заметка под замком). Если потерял - Daniil выдаст новый.

### 3. Открыть хранилище (vault) в Obsidian

Хранилище - это весь репозиторий. Два варианта:

**Вариант A - репозиторий уже есть на компьютере:**

1. Obsidian → **Открыть другое хранилище** → **Открыть папку как
   хранилище** → выбрать папку `boklanov` (ту, что уже склонирована).

**Вариант B - первая установка, репозитория нет:**

1. Сначала склонировать репозиторий через Terminal:
   ```bash
   git clone https://github.com/octrow/boklanov.git
   cd boklanov
   ```
   При запросе пароля - вставить PAT.
2. Затем Obsidian → **Открыть папку как хранилище** → выбрать `boklanov`.

### 4. Включить плагины

Obsidian предложит включить сторонние плагины из репозитория. Согласиться
для обоих:

- **obsidian-git** - кнопка «Commit + Push» в боковой панели.

Если Obsidian не спросил автоматически: **Настройки** (шестерёнка) →
**Сторонние плагины** → убедиться, что плагин включён.

### 5. Настроить obsidian-git

Первый раз плагин попросит авторизацию:

- **Имя пользователя:** твоё имя (например, `Roman Boklanov`)
- **Email:** твой GitHub email
- **Пароль / токен:** PAT от Daniil

### 6. Obsidian Mobile (опционально)

На телефоне: App Store / Google Play → «Obsidian». Повторить шаги 3–5.
На мобильном удобно исправлять текст; большие правки (новые спектакли,
загрузка фото) - только с компьютера.

## Каждый день: как что-то изменить

### Изменить поле спектакля

Поля - это структурированные данные: год, театр, возраст, флаг «главный»,
список городов гастролей и т.д. Лежат в `index.yaml` рядом с текстами.

1. В левой панели Obsidian открыть
   `content/productions/<slug>/index.yaml`. Например:
   `content/productions/bury-me-behind-the-baseboard/index.yaml`.
   Obsidian покажет YAML как простой текст (без панели Properties — это
   нормально, поля — обычные пары `ключ: значение`).
2. Найти нужную строку, ввести новое значение, **Cmd+S** (Ctrl+S на
   Windows).
3. В правой боковой панели — иконка **Source Control** (веточка git) →
   **Commit all changes** → ввести описание («исправил год кашт…») →
   **Commit-and-sync**.
4. Через 1–2 минуты Vercel пересобирает сайт. Открыть
   [boklanov.com](https://boklanov.com) и убедиться, что изменение видно.

**Главные поля (то, что редактируется чаще всего):**

| Поле                  | Что это                                    | Пример                                 |
|-----------------------|--------------------------------------------|----------------------------------------|
| `title.ru`            | Название на русском                        | `Золушка`                              |
| `title.en`            | Название на английском                     | `Cinderella`                           |
| `synopsis.ru`         | Краткое описание (RU)                      | _несколько предложений_                |
| `synopsis.en`         | Краткое описание (EN)                      | _перевод_                              |
| `tagline.ru`          | Подзаголовок над названием на странице     | `Спектакль-воспоминание`               |
| `directorsNote.ru`    | Записка режиссёра под синопсисом           | _текст курсивом_                       |
| `year`                | Год премьеры                               | `2021`                                 |
| `ageRating`           | Возрастное ограничение                     | `6+`                                   |
| `durationMin`         | Длительность в минутах                     | `60`                                   |
| `theatre.name`        | Театр-постановщик                          | `ARTиШОК`                              |
| `theatre.url`         | Сайт театра                                | `https://artishock.kz/`                |
| `featured`            | Показать на главной в featured-стрипе      | `true` / `false`                       |
| `featuredOrder`       | Порядок в featured-стрипе                  | `1` / `2` / `3`                        |
| `listOrder`           | Порядок в полной сетке спектаклей          | целое число или `null`                 |
| `bookingCta`          | Кнопка «Написать о гастролях»              | `true` (показать) / `false` (скрыть)  |
| `bookingCtaLabel.ru`  | Своя подпись для кнопки гастролей          | `Заказать показ`                       |
| `bookingCtaUrl`       | Своя ссылка для кнопки (вместо mailto)     | `https://...`                          |
| `tour`                | Города гастролей «Плинтуса»                | список строк                           |
| `runs`                | Цифры прокатов (появляется над заголовком) | `venue, city, yearFrom, yearTo, count` |

### Мультиязычные текстовые поля (L10nString)

Большинство текстовых полей можно писать **одной строкой** — тогда значение
одинаково на всех языках — или **объектом** с переводами:

```yaml
# Вариант 1 — одна строка (показывается на всех локалях одинаково):
name: «Золотой софит»

# Вариант 2 — отдельный перевод для каждого языка:
name:
  ru: «Золотой софит»
  en: "Golden Spotlight"
  de: null
```

Это работает для следующих полей:

- `theatre.name`, `theatre.shortName`, `theatre.city`
- `awards[].name`, `awards[].category`, `awards[].city`
- `festivals[].name`, `festivals[].category`, `festivals[].city`
- `press[].title`
- `externalLinks[].label`
- `runs[].venue`, `runs[].city`, `runs[].count`

Если нужного языка нет — сайт подставит русский или английский вариант
автоматически.

### Изменить текст описания / синопсис

Длинное описание лежит в отдельных файлах рядом с `index.yaml`:
`bodyRu.mdx`, `bodyEn.mdx`, `bodyDe.mdx`. Их Obsidian открывает как
обычные тексты — редактировать как в Word.

1. Открыть нужный файл (например, `bodyRu.mdx`).
2. Править текст. Пустая строка между абзацами = новый абзац.
   `**жирный**`, `_курсив_`, `[ссылка](url)` работают как обычно.
3. **Cmd+S** → **Commit-and-sync**.

Короткие тексты (`title`, `synopsis`, `directorsNote`, `tagline`) лежат
в `index.yaml`. Править как обычное поле (см. выше).

### Добавить фотографии на страницу «О режиссёре»

Фото появляются в двухколоночной сетке под блоком «Где ставил».

1. Положить файлы в `public/about/` (форматы `.webp`, `.jpg`).
2. Открыть `content/about/ru.yaml` в Obsidian, найти строку `photos:`.
3. Добавить запись:
   ```
   photos:
     - src: /about/имя-файла.jpg
       credit: "Имя Фотографа"
   ```
4. Повторить для `content/about/en.yaml` — те же записи.
5. **Cmd+S** → **Commit-and-sync**.

Пустой список `photos: []` = секция не отображается.

### Добавить новый спектакль

1. Открыть файл-шаблон `content/_PRODUCTION_TEMPLATE.yaml`. Там перечислены
   все поля с комментариями.
2. Создать новую папку `content/productions/<slug>/` (slug — латиница,
   дефисы вместо пробелов; пример: `solnyshko`, `novaya-postanovka`).
3. Скопировать шаблон в `content/productions/<slug>/index.yaml`
   и поменять поле `slug` на имя папки.
4. Создать в той же папке файлы описаний:
   - `bodyRu.mdx` — длинный текст по-русски
   - `bodyEn.mdx` — то же по-английски
   - `bodyDe.mdx` — по-немецки (опционально)
5. Заполнить поля в `index.yaml`. Поля, которые пока неизвестны,
   оставить как `null` или пустой список — они просто не появятся на сайте.
6. Положить фотографии в ту же папку (форматы: `.webp`, `.jpg`).
7. В поле `gallery` (внутри `index.yaml`) добавить записи вида:
   ```
   - src: /productions/<slug>/01.jpg
     credit: null
     caption:
       ru: null
       en: null
   ```
8. Commit-and-sync — сайт пересобирается, фото автоматически уходят в
   R2 (CDN) через GitHub Action, новый спектакль появляется на
   `/ru/productions` через 1–2 минуты.

> Совет: если хочется подсмотреть, как заполнен реальный спектакль со всеми
> полями (награды, пресса, гастроли) — открыть
> `content/productions/bury-me-behind-the-baseboard/index.yaml` и
> `body.ru.md`.

### Заменить или добавить фотографии существующего спектакля

1. Положить новые файлы в `public/productions/<slug>/`.
2. Удалить старые файлы из той же папки (если заменяешь).
3. Обновить поле `gallery` в `index.yaml` — список `src` должен
   соответствовать файлам в папке.
4. Commit-and-sync — фото автоматически уйдут в R2 через GitHub Action.

## Черновики (если правка большая или сомнительная)

Например, добавляешь три новых спектакля и не уверен в текстах.

1. В Source Control → **кнопка «ветка»** → создать ветку `draft/<описание>`.
   Например: `draft/three-new-shows`.
2. Все правки коммитятся в эту ветку. Vercel создаёт **отдельный preview
   URL** — автоматически, прилетает ссылкой в GitHub. Открыть, проверить.
3. Если всё ок: написать Daniil, он смержит ветку в `main`.
4. Если не ок: продолжить редактировать либо удалить ветку (ничего не
   пропадёт в `main`).

## Что-то сломалось

**Сайт не обновился через 5 минут**
→ Открыть [github.com/octrow/boklanov/actions](https://github.com/octrow/boklanov/actions).
Красный значок = билд упал. Скопировать ошибку → Daniil.

**obsidian-git ругается «merge conflict»**
→ Не паниковать. Нажать **Pull** (стрелка вниз) в Source Control, потом
написать Daniil — он покажет, как разрешить конфликт за 2 минуты.

**Случайно опубликовал что-то лишнее**
→ Всё в порядке. Поправить и сделать новый commit-and-sync.
История в git — ничего не теряется.

**Забыл PAT**
→ Написать Daniil — выдаст новый за пару минут.
